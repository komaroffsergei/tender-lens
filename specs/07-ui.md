# 07. Статический интерфейс

## 1. Цель

Интерфейс нужен только для короткой демонстрации backend-функций. Он не является отдельным frontend-проектом.

Эталон: `docs/ui/search-wireframe.png`.

## 2. Технологии

- semantic HTML;
- один CSS-файл;
- один JavaScript module;
- `fetch` и DOM API;
- без npm, bundler, CDN, framework, RxJS или Signals.

## 3. Экран

Одна responsive-страница содержит:

1. Header: название TenderLens и индикатор состояния API.
2. Блок API key:
   - password input;
   - кнопка «Сохранить на сессию»;
   - текст, что ключ хранится только до закрытия вкладки.
3. Поисковая форма:
   - textarea/query input;
   - переключатель `Поиск` / `Ответ по базе`;
   - кнопка отправки.
4. Строка состояния лимита после ответа.
5. Answer panel для `/ask`.
6. Result cards с title, source badge, score, snippet и ссылкой на исходную карточку.
7. Ненавязчивый блок ограничений MVP.

## 4. Состояния

### Initial

Короткая инструкция и пример запроса.

### Loading

Кнопка disabled, `aria-busy=true`, видимый текст «Обрабатываем запрос…».

### Success search

Карточки результатов отсортированы по score.

### Success ask

Сначала answer, затем источники.

### Empty

«Подходящие фрагменты не найдены».

### 401/403

«Проверьте API-ключ» без вывода его значения.

### 429

Показать, через сколько секунд повторить запрос, используя `Retry-After`.

### 503

«Сервис модели или база временно недоступны».

### Validation

Понятное сообщение для слишком короткого/длинного запроса.

## 5. Безопасность

- API key хранится только в `sessionStorage`;
- ключ не добавляется в URL, DOM text или console;
- все внешние строки вставляются через `textContent`;
- ссылки проверяются как HTTP(S), используют `rel="noopener noreferrer"`;
- `innerHTML` разрешён только для статичной заранее заданной разметки, но проще не использовать его вообще;
- ошибки API не выводят stack trace.

## 6. Accessibility

- каждому input соответствует label;
- формы доступны с клавиатуры;
- видимый focus;
- статус ответа использует `aria-live="polite"`;
- цвет не является единственным носителем состояния;
- контраст текста достаточен;
- score имеет текстовое значение.

## 7. Responsive

- desktop: форма слева, справка/статус справа; результаты на всю ширину;
- mobile: одна колонка;
- минимальная ширина без горизонтального скролла: 360 px.

## 8. UI acceptance

- root отдаёт HTML;
- assets локальные;
- отсутствуют npm manifest и внешние script/style URLs;
- query можно отправить клавиатурой;
- session key переживает reload вкладки, но не закрытие browser session;
- 401, 429 и 503 отображаются различимо;
- данные не интерпретируются как HTML.
